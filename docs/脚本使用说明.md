# 脚本功能与使用说明

项目脚本位于 `scripts/`，建议在项目根目录执行。Python 环境为 conda 环境 `dba-py311`。下面的命令均为单行，可直接复制执行。

## `reprocess_documents.py`

重新生成解析结果。默认只读取已有的 `structure.json`，重新构建 `doc.json` 和 `doc.md`，不会重新渲染 PDF、调用 PP-StructureV3 或检测水印。

使用 `--full` 时才会执行完整流程：PDF 渲染、版面/OCR 检测、后处理；水印预处理默认开启，会检测并弱化重复的橙色 GJB 水印。原始 PDF 不会被修改。

常用命令：

```powershell
conda run -n dba-py311 python scripts/reprocess_documents.py --gjb-only
```

```powershell
conda run -n dba-py311 python scripts/reprocess_documents.py --full --gjb-only
```

```powershell
conda run -n dba-py311 python scripts/reprocess_documents.py --full --watermark-preprocessing --limit 1
```

参数说明：

- `--papers-only`：只处理论文目录中的 PDF。
- `--gjb-only`：只处理国军标目录中的 PDF。
- `--full`：重新渲染并重新检测；需要模型环境，耗时较长。
- `--limit N`：最多处理 N 个 PDF。
- `--no-watermark-preprocessing`：关闭完整流程中的水印预处理。
- 也可以直接在命令后给出一个或多个 PDF 路径；不指定路径时按范围选项枚举输入目录。

输出通常写入 `processed/parsed/<文档ID>/`，包括 `doc.json`、`doc.md`、`structure.json`、页面图和裁剪资源。



## `validate_watermark.py`

专门验证 GJB 橙色水印清洗效果。脚本会渲染 PDF、检测重复水印、生成清洗后的 PDF，并检查像素变化、页面完整性和源文件哈希，最后输出 JSON/Markdown 报告及前后对比图。

用法：

```powershell
conda run -n dba-py311 python scripts/validate_watermark.py <输入PDF> <空的输出目录>
```

示例：

```powershell
conda run -n dba-py311 python scripts/validate_watermark.py 资料/国军标/无人机通用规范.pdf processed/watermark_validation/uav
```

可选参数：`--dpi N` 设置渲染 DPI，默认 200。输出目录必须不存在内容；主要产物是 `watermark_cleaned.pdf`、`validation_report.json`、`VALIDATION.md`、`watermarks.json` 和 `comparisons/`。



## `analyze_gjb.py`

统计已解析的三个 GJB 文档，并打印解析质量概览。脚本读取 `processed/parsed/<文档ID>/doc.json`，统计页数、block 类型、来源方式、标题层级、图注配对、引用数、段落平均长度及空/极短段落数量；找不到对应 `doc.json` 时会提示跳过。

用法：

```powershell
conda run -n dba-py311 python scripts/analyze_gjb.py
```

脚本当前固定分析：`7-装甲车辆和军用汽车`、`建（构）筑物地震破坏等级划分`、`无人机通用规范`。论文基线会一并打印，供人工比较；脚本不会修改文件。



## `batch_mllm_charts.py`

批量调用 OpenAI 兼容接口（默认面向 LM Studio）为解析结果中的 `figure` 和 `table` 生成视觉描述。结果写入每个文档目录下的 `visual_enrichment.json`，不会改写 `doc.json`；已有成功条目默认跳过，可用 `--force` 重做。

前提：先在本机启动兼容 OpenAI API 的视觉模型服务，并确认模型名和接口地址。

处理全部已解析文档：

```powershell
conda run -n dba-py311 python scripts/batch_mllm_charts.py --model qwen/qwen3.5-9b
```

处理指定文档：

```powershell
conda run -n dba-py311 python scripts/batch_mllm_charts.py --doc processed/parsed/2-电子系统/doc.json --model qwen/qwen3.5-9b
```

常用参数：

- `--parsed-root PATH`：指定解析结果根目录，默认 `processed/parsed`。
- `--doc PATH`：指定一个文档，可重复传入多个 `--doc`。
- `--model NAME`：服务端加载的视觉模型名称，必填。
- `--base-url URL`：API 地址，默认 `http://localhost:1234/v1`。
- `--limit N`：最多处理 N 个文档。
- `--force`：重新处理已有成功结果。
- `--retries N`：文档级失败重试次数。
- `--failure-log PATH`：将文档级失败写入 JSON 文件。

## 推荐执行顺序

首次或需要重新识别 PDF 时，先运行 `reprocess_documents.py --full`；只调整解析后处理规则时运行不带 `--full` 的版本。需要确认水印清洗质量时单独运行 `validate_watermark.py`。解析完成后，如需图表语义描述，再启动视觉模型并运行 `batch_mllm_charts.py`；无论视觉增强是否完成，都可以运行 `build_chunks.py` 生成检索块；最后可用 `analyze_gjb.py` 汇总 GJB 文档统计。

## `build_chunks.py`

从解析层正式产物 `doc.json` 生成同目录下的 `chunks.jsonl`。默认按完整章节路径约束边界，以结构化块为最小单元，并保留页码、块 ID、引用和图表裁图回链。`visual_enrichment.json` 缺失或单项失败不会阻塞切分。

```powershell
conda run -n dba-py311 python scripts/build_chunks.py --all
```

指定单篇时直接传入 `doc.json` 路径。默认目标 600 字、上限 800 字、重叠 80 字，可分别用 `--target-chars`、`--max-chars`、`--overlap-chars` 调整。字段契约和策略详见 `docs/chunking.md`。
