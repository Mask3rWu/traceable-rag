# 开发主线

> 本文件记录项目当前的开发主线与各层边界,只给大方向。
> 各环节的具体实现方案另起文件;已实现的解析层见 `pdf-parser.md`,其产物说明见 `解析输出结构.md`。
> 后续开发中若主线调整,以本文件为准,过时内容应及时移除。

## 1. 项目定位

构建面向行业标准、技术规范与领域文献的**通用可溯源 RAG**,并在此基础上实现领域研究 Agent。系统支持三类任务:

1. **专家问答**:回答领域问题并给出原文依据。
2. **深度研究**:围绕主题跨文档检索、比较来源、分析冲突。
3. **标准生成**:按给定结构系统研究并生成带依据的评估标准。

标准生成是通用 RAG 与研究 Agent 的一种任务封装,不是知识库的唯一用途。当前首个落地场景为视觉毁伤评估准则构建。

## 2. 总体架构

```text
行业标准 / 技术规范 / 领域文献
        ↓
  原始资料与知识库   (解析、结构恢复、切块)
        ↓
  通用可溯源检索     (混合召回、Rerank、来源回显)
        ↓
  领域研究 Agent     (ReAct,证据与冲突持久化)
        ↓
  任务封装           (问答 / 深度研究 / 标准生成)
        ↓
  评估标准、机器规则、溯源报告
```

各层保持明确边界,不把"知识库构建""检索""标准生成"混为一个步骤。

## 3. 各层职责与边界

- **资料与知识库层**:文档解析、版面与章节恢复、块间关系建立、结构化切块。解析层已实现,方案见 `pdf-parser.md`。
- **检索层**:返回与问题相关、可回溯的原始证据,不直接生成标准。支持快速检索(问答)与研究检索(多轮扩大覆盖)。
- **研究 Agent 层**:用 ReAct 决定检索词、过滤与工具调用,关键过程由显式工作流约束;证据、候选结论、冲突记录必须持久化。
- **任务封装层**:在 Agent 之上封装问答、深度研究、标准生成三种模式。

**贯穿各层的约束:**

- **结论类型**:`direct`(原文明确规定)/ `synthesized`(多来源综合)/ `hypothesis`(为适配场景自拟,需验证)。
- **视觉可判断性**:`single_image` / `multi_frame` / `non_visual` / `uncertain`。无法从图像可靠判断的内容(尺寸阈值、内部功能状态等)只能作辅助信息,不能当作视觉证据。
- **v0 的定位**:`资料/DBA-MLLM.md` 仅作"最终标准应包含哪些内容"的结构模板,不将其具体规则视为已验证事实,也不作检索来源。

## 5. 实施路线

1. **解析层**:稳定复杂 PDF 的 OCR、版面、章节与关系恢复(已完成)。
2. **通用 RAG**:结构化切块、BM25+向量索引、混合召回与 Rerank、来源回显;用人工问题集验证召回与引用准确率。
3. **研究 Agent**:封装检索、上下文扩展、引用核验工具;实现问答与深度研究;持久化证据与冲突。
4. **标准生成**:将 v0 转为章节任务,按章节研究、缺口检查、规则综合;生成标准与溯源产物。
5. **验证与应用**:检查证据覆盖率与引用正确率;专家审核冲突与综合规则;对比接入结构化标准前后的 MLLM 评估效果。

## 6. 标准生成输出

- `standard.md`:供人工阅读与 MLLM 使用的评估标准;
- `rules.json`:机器可读的等级、特征与判定规则;
- `traceability.json`:规则到原始文档、章节、页码与内容块的映射。

决策树由已确认规则生成,MLLM Prompt 由最终标准生成,示例根据规则构造并标注为生成内容,以减少标准内部不一致。
