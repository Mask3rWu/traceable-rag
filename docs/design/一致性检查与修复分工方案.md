# 一致性检查与修复分工方案

> 状态：设计记录（未实现）
> 适用范围：`src/research` 下 supervisor 路由的一致性检查（`_structural_consistency_issues`）与修复（`_revise_reviewed_chapters`）
> 关联：《章节Worker输出重构设计方案.md》（契约机制）、《../开发主线.md》（研究 Agent 层）
> 背景：`b_20260816_0014` 批次评估暴露 terminology-drift 自动检查大量贪婪子串误报，污染交付物 limitations、触发无意义章节重跑、误导 judge 一致性评级。

## 1. 问题现状（b_20260816_0014 实测）

- q7/q8/q9 的 terminology-drift 分别 73/195/274 条，绝大多数为贪婪子串误报（如 `期核辐射`←`早期核辐射`、`束为毁伤`←"光束为毁伤"、`结构毁伤`），非真实术语越界。
- 误报以 `severity=error` 进 `_structural_consistency_issues`，于是：
  1. `_revise_reviewed_chapters` 对几乎所有章节触发**整章重跑**（费钱费时，supervisor 模型调用/题反升至 ~133）。
  2. `_assemble_answer` 把每条 error 的 description 追加进交付物 limitations（q7 61/83、q8 130/146、q9 208/228 行为误报），并挤占证据 token 预算。
  3. judge 读几百条 error，一致性被压到 C，真实跨章矛盾被淹没。

- 结构根源：术语检查同时存在于两个位置，都不在单章提交门内——① 模型可自调的 `check_terminology` 工具（自愿）；② graph 级 review 的 prose 扫描（graph.py:1104-1141，事后强制）。

## 2. 检查分类框架

判断某项检查该放"单章提交门（门 1）"还是"跨章 review（门 3）"，看一句话：**"能否只用这一章 packet + 它的上游契约判定？"**
- 能 → 应在单章提交时就地检查、让模型当场改（便宜、即时）。
- 必须看到全部章节产物 → 才留到跨章 review。

| 检查 | 单章可判定 | 归属 | 是否适合 LLM reviewer 自修 |
|---|---|---|---|
| prose/rules 预算、无标题、无内部 ID | ✅ | **门 1**（已在 `_validate_packet`） | ❌ 结构校验，提交时拦截 |
| 契约 ID 唯一、terms 契约有 canonical | ✅ | **门 1**（已在） | ❌ 同上 |
| `dangling-rule-contract`（rules 引用未声明契约） | ✅ | **门 1**（已在，`_validate_packet` 会 raise） | ❌ 提交时阻塞项 |
| `missing-contract`（计划产出未产出） | ✅ | **门 1**（应下沉，当前在门 3） | ❌ 提交时拦截，不该拖到 review |
| **`terminology-drift`（非规范词）** | ✅ | **门 3**（本方案决策） | ✅ **由 LLM reviewer 自检自修** |
| `contract-conflict`（同契约跨章定义不一） | ❌ | 门 3 | ✅ 适合，reviewer 见双方裁定 |
| `unmet-contract`（消费契约无人产出） | ❌ | 门 3 | ⚠️ 规划缺口，reviewer 修不动，应回 planner |
| `chapter-insufficient` | N/A | 门 2（补跑） | ❌ 需重新研究，非"修" |
| `open-conflict` | N/A | 门 3（仅报告） | ❌ 披露项，非缺陷 |

## 3. 决策：非规范词（terminology-drift）检查与修复放置于门 3

**非规范词的检查与修复由跨章 review 阶段（门 3）的 LLM reviewer 承担**：reviewer 在 `ConsistencyReport` 中直接对 prose 做规范词审查，发现非规范词时**自行修复受影响章节**（就地改 prose/契约），不再触发整章重跑。

理由：
- 术语受控本质是"跨章共用一个词表"的契约一致性问题，由能看到全局契约的 reviewer 判断最合适。
- 术语修复是**内容级微调**（换词、统一口径），不需要新一轮检索/研究，适合 reviewer 就地改，而非 `_run_chapter` 整章重跑。
- 与 reviewer 已承担的真实跨章矛盾（如契约冲突）同属"跨章内容一致性"，归并到一处，单一职责。

落点要求：
1. **移除**模型可自调的 `check_terminology` 工具（graph.py:486）及 prompt 引导（graph.py:497-503）。
2. **移除** graph 级 review 的 prose 术语扫描（graph.py:1104-1141），改由 reviewer 在 `ConsistencyReport` 中产出术语类 issue 并自修。
3. 术语检查交给 reviewer 后，**不再需要机器侧的 `scan_terminology` 正则扫描**；其精度问题（贪婪子串误报）随之消失，不再污染交付物。

### 遗留：修复机会的语义

门 1 的 schema 校验是"失败→喂回→循环修复直到通过"。术语在门 3 由 reviewer 自修时，建议用**单次修复、不复检**语义（改一次即接受），避免在残余问题上打转。具体由实现时以 reviewer 输出为准。

## 4. 建议：机械/契约追踪类检查下沉到门 1

除术语外，`missing-contract` 等机械/契约追踪类检查**应下沉到单章提交门**，让模型在上交前当场改掉，不与"重新研究"搅在一起：

- `missing-contract`（计划产出未产出）：单章可判定，应在提交时拦截。
- 现状 `dangling-rule-contract` 已在门 1 却又在门 3 重复扫描（graph.py:1087），属重复，应去重（门 1 已覆盖）。

## 5. 建议：门 3 修复从"整章重跑"改为"reviewer 就地自修"

当前 `_revise_reviewed_chapters` 对任何 error 都重新 `_run_chapter`（整章检索+研究），对两类问题都不合适：
- **机械问题**：重研究不会因"漏写契约"自动补上，只是运气。应在门 1 拦截。
- **内容问题**：跨章冲突只需"看两章、裁定、改一处"，却触发整章重研究。

建议门 3 只保留真正需要全貌的（`contract-conflict`、术语、`unmet-contract`），修复方式改为 **LLM reviewer 就地自修**（改受影响章节 prose/契约），不再触发新研究。

## 6. 落地顺序

1. 门 3 方案：reviewer 承担非规范词检查与自修；移除 `check_terminology` 工具、prompt 引导、graph 术语扫描。
2. 门 1 下沉：`missing-contract` 等机械检查下沉到提交门，去重 `dangling-rule-contract`。
3. 门 3 修复方式：`_revise_reviewed_chapters` 由整章重跑改为 reviewer 就地自修。
4. 用 q7/q8/q9 三个 supervisor 题重跑，对比：术语误报是否归零、交付物 limitations 是否干净、supervisor 模型调用/耗时是否下降、judge 一致性是否回到真实水平。
