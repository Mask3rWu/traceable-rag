# PDF 解析输出结构说明

本文档说明单篇 PDF 完成解析后生成的目录结构、各类产物的区别，以及后续处理应选择的输入。

## 1. 目录结构

每篇 PDF 的输出位于：

```text
processed/parsed/{document_id}/
├─ structurev3.json
├─ structurev3.md
├─ doc.json
├─ doc.md
├─ pages/
│  ├─ p001.png
│  ├─ p002.png
│  └─ ...
└─ assets/
   ├─ imgs/
   ├─ crops/
   └─ figures/
```

其中，`structurev3.*` 是 PP-StructureV3 的原始产物，`doc.*` 是经过归一化和关系补全后的正式产物。

## 2. 四个主文件

### 2.1 `structurev3.json`

PP-StructureV3 的原始 JSON，用于模型排错和重新运行后处理。

主要特点：

- 按页保存模型原始结果；
- 包含 `parsing_res_list`、`layout_det_res`、`overall_ocr_res` 和模型设置；
- 坐标使用模型推理时的页面尺寸；
- 保留页眉、页码、公式编号等原始标签；
- 可能出现版面检测已发现图片、但 `parsing_res_list` 没有图片块的情况；
- 数据量较大，不适合作为后续切分和检索的直接输入。

典型用途：

- 检查 OCR、版面检测和公式识别的原始结果；
- 调整后处理规则后，通过 `--reuse-detection` 重建正式产物；
- 排查漏图、错误标签和模型置信度问题。

### 2.2 `doc.json`

解析层的正式结构化结果，也是后续切分、证据抽取和检索的主要输入。

相对于原始 JSON，它完成了以下增强：

- 去除页眉、页脚和页码等噪声；
- 将原始标签统一为 `heading`、`paragraph`、`table`、`formula`、`figure`、`caption` 等块类型；
- 将检测坐标转换到 `pages/` 高分辨率页图坐标，并同时保存 `[0,1]` 归一化坐标；
- 为文档、页面和内容块分配可寻址 ID；
- 保存 `section_path`、附录属性和阅读顺序；
- 通过 `caption_ids` 和 `caption_of` 建立图片与一个或多个图注的关系；
- 通过 `references` 建立正文到图片、表格、公式和章节的引用；
- 通过 `continuation_of` 和 `continues_to` 连接跨栏、跨页正文；
- 通过 `quality_flags` 标记跨页公式等需要复核的内容；
- 将公式编号保存在公式块的 `formula_no` 中，不再把 `(1)`、`(2)` 作为独立公式图片。

后续程序应优先读取 `doc.json`，不应直接依赖 `structurev3.json` 的内部字段。

### 2.3 `structurev3.md`

PP-StructureV3 原始结果的 Markdown 视图，主要用于观察模型直接输出。

主要特点：

- 内容基本来自 `parsing_res_list`；
- 页序已按数字页码合并；
- 图片通常引用 `assets/imgs/`；
- 不包含后处理从 `layout_det_res` 补回的全部图片；
- 不包含跨页续接、增强引用和最终裁图关系；
- 可能保留 OCR 错字、错误块顺序或不完整图文关系。

该文件是诊断产物，不应作为最终 Markdown 或正式机器输入。

### 2.4 `doc.md`

根据 `doc.json` 生成的最终人工审阅版本。

主要特点：

- 使用增强后的全文阅读顺序；
- 合并已识别的跨栏、跨页正文；
- 展示从版面检测结果中补回的图片；
- 图片引用指向清理后的 `assets/crops/`；
- 按原版顺序展示中文、英文等多个图注；
- 显示公式本体及独立保存的公式编号；
- 使用 Markdown 注释记录 `continued-sources` 和 `quality-flags`，便于追溯而不干扰正文阅读。

人工检查解析效果时应优先查看 `doc.md`。

## 3. 页面和图片目录

### 3.1 `pages/`

PDF 的完整逐页渲染图，例如 `pages/p003.png`。

- 默认按解析配置中的 DPI 渲染；
- 是最终图片、表格和公式重裁的图像来源；
- 用于把 `bbox_pixel` 回显到原页面；
- 用于人工核对版面、阅读顺序和 OCR 结果；
- 不直接作为单个图表的输入。

### 3.2 `assets/imgs/`

PP-StructureV3 自动生成的原始裁图。

文件名通常记录模型检测坐标，例如：

```text
img_in_image_box_150_318_537_477.jpg
img_in_formula_box_734_736_950_760.jpg
```

主要特点：

- 使用模型内部页面尺寸和原始检测框；
- 与 `structurev3.json`、`structurev3.md` 对应；
- 可能裁切过紧；
- 可能包含部分中文图注；
- 可能没有反映后处理补回的视觉块关系。

该目录用于原始结果留底和排错，不作为默认视觉模型输入。

### 3.3 `assets/crops/`

从 `pages/` 高分辨率页图重新生成的纯内容裁图。

主要特点：

- 包含 `figure`、`table` 和 `formula` 等视觉块；
- 在图片主体周围保留少量安全边界；
- 已配对的中文、英文图注会从图片主体中剥离；
- 公式裁图只保留公式本体，编号保存在 `doc.json` 的 `formula_no`；
- 是 `doc.md` 使用的图片；
- 是后续 MLLM、图片回显和证据定位的默认视觉输入。

### 3.4 `assets/figures/`

包含图片主体及全部已配对图注的上下文裁图。

主要特点：

- 由图片框与所有关联 caption 的坐标并集生成；
- 双语论文通常同时包含中文图注和英文图注；
- 适合人工确认图片与图注是否正确配对；
- 适合需要观察原始排版上下文的复核任务；
- 不作为默认 MLLM 输入，避免图注文字与 `doc.json` 中的结构化文本重复。

只有成功关联图注的 `figure` 或 `table` 才会生成对应的上下文裁图。

## 4. 图片字段对应关系

一个视觉块在 `doc.json` 中可能包含以下字段：

| 字段 | 含义 |
|---|---|
| `image_crop_raw` | PP-StructureV3 原始裁图，对应 `assets/imgs/` |
| `image_crop` | 清理后的纯内容裁图，对应 `assets/crops/` |
| `figure_crop` | 主体加全部图注的复核裁图，对应 `assets/figures/` |
| `bbox_pixel` | 模型检测框转换到页图后的坐标 |
| `crop_bbox_pixel` | 实际纯内容裁图在页图上的坐标 |
| `figure_crop_bbox_pixel` | 上下文复核裁图在页图上的坐标 |

对同一图片，这三个文件承担不同职责，不应互相覆盖。

## 5. 推荐使用方式

| 使用场景 | 推荐产物 |
|---|---|
| 后续切分、证据抽取、RAG | `doc.json` |
| 人工阅读和解析质量检查 | `doc.md` |
| MLLM 图片、表格、公式输入 | `assets/crops/` |
| 人工检查双语图注配对 | `assets/figures/` |
| 页面坐标回溯 | `pages/` + `doc.json` |
| 调试 PP-StructureV3 原始输出 | `structurev3.json`、`structurev3.md`、`assets/imgs/` |
| 只修改后处理规则后重跑 | `structurev3.json` + `--reuse-detection` |

## 6. 数据流关系

```text
原始 PDF
  ├─> pages/                         完整页面渲染
  └─> PP-StructureV3
       ├─> structurev3.json          原始机器结果
       ├─> structurev3.md            原始审阅视图
       └─> assets/imgs/              原始模型裁图

structurev3.json + pages/
  └─> 归一化、补图、关系构建、跨页续接、重裁
       ├─> doc.json                  正式机器结果
       ├─> doc.md                    最终人工审阅视图
       ├─> assets/crops/             纯内容裁图
       └─> assets/figures/           图片及图注复核裁图
```

简要原则：原始结果用于排错，增强结果用于消费；纯内容裁图用于模型，带图注裁图用于人工复核。
