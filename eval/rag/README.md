# 检索评估候选集

本目录保存与当前 chunk 策略解耦的检索评估数据。候选题直接标注到解析层
`doc.json` 的稳定 `block_id`，不以 `chunks.jsonl` 作为标注依据。

## v1 字段

- `question_id`：题目稳定 ID。
- `question`：提交给检索系统的自然语言问题。
- `evidence_block_ids`：回答问题必须覆盖的最小充分证据集合；列出多个 ID 时默认全部需要。
- `source_granularity`：问题文本中的来源提示类型：
  - `none`：问题没有提及资料来源，但仍有明确的证据块；
  - `document_approximate`：只给出模糊的文件主题或资料类型；
  - `document_exact`：给出准确的文件名或标准号；
  - `section_approximate`：描述文件中的大概章节或内容位置，但不知道准确章节号；
  - `section_exact`：给出准确章节号。

可以通过 `evidence_block_ids` 查询 `doc.json`，获得文档、页码、章节和坐标，
因此候选集不重复存储这些可推导字段。

## 首版约束

### 目标与范围

- 第一版用于评估 chunk 和检索能否召回正确证据，不评估最终回答质量。
- 直接从文档生成候选题，不把“全库主题和术语索引”作为前置步骤；主题清单可在后续批量生成和审计时自然沉淀。
- 当前 `v1/` 按解析资料一文档一文件保存候选题；`2-电子系统.jsonl` 是首个单文档样例，共 25 题。
- 第一版暂不进行全库主题覆盖优化、语义去重、跨文档冲突分析、标准版本和权威性判定，也不构造困难负例。

### 来源提示

- 不提示来源与提示来源的总比例约为 80%/20%。
- 对于提示来源的问题，不能假设用户准确知道标准号、完整文件名或章节号；应以模糊文件主题、资料类型或大概内容位置为主，同时保留少量精确来源问题以覆盖对应场景。
- `2-电子系统.jsonl` 的 25 题中，`none` 20 题、`document_approximate` 3 题、
  `document_exact` 1 题、`section_approximate` 1 题。全库的来源提示比例应保持约 80%/20%。
- `none` 仅表示问题文本没有资料来源提示，不表示题目没有来源或证据。这类问题仍应包含必要的对象、条件或场景，不能为了增加检索难度而写成缺乏语义约束的宽泛问题。

### 标注依据

- 使用 `doc.md` 阅读和选择候选内容，使用 `doc.json` 标注稳定的 `evidence_block_ids`。
- 使用原 PDF、`pages/` 页面图或视觉块裁图核验原文；MLLM 视觉描述只能辅助理解，不能作为标准证据。
- 不依据当前 `chunks.jsonl` 定义正确答案，确保测试集可以公平比较不同 chunk 策略。
- `evidence_block_ids` 表示回答问题必须覆盖的最小充分证据集合；一题列出多个 ID 时，默认这些块全部需要召回，而不是任选其一。

### 字段取舍

- 第一版只保留 `question_id`、`question`、`evidence_block_ids` 和 `source_granularity`。
- 文档、页码、章节和坐标均通过 `evidence_block_ids` 从 `doc.json` 查询，不在候选集中重复存储。
- 暂不保存 `topic`、`terms`、`status` 等非必要字段。
- `reference_answer` 留到问答评估阶段再添加；本版本只评估证据检索。

## 已知评测偏向

除最早单独编写的 `2-电子系统` 25 题外，当前题目由历史批量流程
直接读取证据块并按规则生成。该集合适合验证索引链路、
chunk 覆盖与原文回查，不适合单独决定 Dense/BM25 权重或是否引入 Reranker。

当前快照的审计结果：

- 2058 道批量生成题中，1983 道使用 5 种固定尾句之一；
- 问题与证据的最长连续匹配片段平均占问题规范化字符数的 52.8%；
- 2058 道中有 1287 道的连续原文匹配比例不低于 50%；
- 全集只有 11 道多证据题，不能代表跨文档研究和完整证据覆盖场景；
- 当前没有困难负例，且部分题目保留列表符号、OCR 截断或不完整语义片段。

后续应另建独立评测集，覆盖语义改写、标准号/阈值精确查询、表格与公式、跨文档
多证据、同词异义困难负例和来源过滤。`v1` 保留为词法回查与回归测试集。

## v2 目录约定

`v2/` 与 `v1/` 一样采用一篇文章一个同名 JSONL 文件的扁平结构，不保存生成候选、
分片、审核日志或其他中间产物。跨文章问题如需加入，统一保存到
`v2/cross_document.jsonl`，不计入逐文章题量目标。
