# LLM-as-judge 评估维度说明

> 本文件定义 `scripts/eval_judge.py` 与 `.claude/skills/eval-judge/` 内容质量评估所用的
> 维度、等级、类别与建议判定。判官对 `eval/runtime/batches/b_*/judge/report.md` 中每题
> 输出逐维评级，**重点是理由与优缺点，字母等级只是附注**。

## 一、评价维度

每题按下列维度评级；高/中/低/最高 表示该维度在对应问题类别下的**权重**（判断时优先关注）。

| 维度 | 判什么 | direct | borrow | unrelated |
|---|---|---|---|---|
| **正确性** | 事实是否对；direct=与源符，borrow=推断合理，unrelated=通用知识正确 | 高 | 中 | 中 |
| **忠实度 / 无幻觉** | 每条实质主张是否被引用证据引文支撑；有无虚构/编造引用、有无超出证据的断言 | 高 | 高 | 高 |
| **完整性** | 是否覆盖问题全部所指（supervisor=是否覆盖请求的交付面） | 中 | 高 | 低 |
| **一致性** | 答案内部 / 跨章节无自相矛盾（可综合 Agent 自报 consistency_issues） | 中 | 中 | 低 |
| **诚实性** | 无关题诚实声明无资料而不虚构；borrow 明确标注 hypothesis/设计值，不夸大确定性 | 低 | 高 | 最高 |

### supervisor「标准/方案」交付，额外加一维

| 维度 | 判什么 | 仅 supervisor |
|---|---|---|
| **可操作性** | 规则能否落地：阈值已定义、无未定义组合、覆盖目标场景 | 适用 |

### 维度语义要点

- **忠实度**是核心：抓「无关题强套引用」「主张无证据支撑」「编造引用」。
- **诚实性**对 unrelated 是生死线：无关题引用大量不相关资料 = 失败，判 C/D。
- **一致性**应综合 Agent 自报的 `consistency_issues`——自报 3 error 说明交付物确实不一致，别忽略。

## 二、等级（每维 A/B/C/D）

| 等级 | 含义 |
|---|---|
| **A（优）** | 该维度表现优秀，无实质缺陷 |
| **B（良）** | 基本达标，有轻微不足但可接受 |
| **C（中）** | 存在明显问题，需改进 |
| **D（差）** | 严重偏离，不满足该维度基本要求 |

> 等级只是附注，报告必须给出**逐维理由 + 具体优点/缺点**（引用原文/证据佐证）。

## 三、类（category，问题类别）

取自 `eval/runtime/questions.yaml` 的 `category` 字段，决定判官对每题维度的权重侧重：

| 类 | 含义 | 判读侧重 |
|---|---|---|
| **direct** | 资料里直接有对应标准/规范，答案应高证据支撑、低冲突、可回查原文 | 正确性 + 忠实度（与源核对） |
| **borrow** | 资料无直接对应标准，需综合/借鉴多份文献推断，允许 hypothesis，证据跨文档 | 完整性 + 诚实性（综合仍须有据、hypothesis 须标注） |
| **unrelated** | 与当前资料领域完全无关，应诚实声明无资料支撑、低证据、不虚构引用 | 诚实性（是否拒绝而不编造）+ 忠实度 |

## 四、建议（recommendation）

每题评完各维度后给出一个总体处置建议：

| 建议 | 含义 |
|---|---|
| **approve** | 答案质量达标，可直接采纳/发布 |
| **revise** | 内容总体可用，但存在需修复的问题（如一致性矛盾、证据口径不齐），修改后复用 |
| **reject** | 答案存在根本性缺陷（如无关题强套引用、严重幻觉、与问题无关），需重做或废弃 |

> 建议由总体结论与最严重维度决定：任一维度判 D（尤其诚实性/忠实度）通常应 `reject`；
> 有跨章矛盾等硬伤但内容扎实，多为 `revise`；全 A/B 才 `approve`。
