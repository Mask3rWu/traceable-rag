## 对比 #1：b_20260816_0014 vs b_20260811_1957_backfill

> 本轮改动主要依据《docs/章节Worker输出重构设计方案.md》（**部分实现**，完成 §8 落地顺序第 1 步）
> 相关提交：`6b3df4a`（核心重构）· `6dbcb10`（rationale 必填）· `c7621ac`（batch 运行提交）

### 一、改动内容与改动原因

#### 改动内容
1. **删除三层输出** ContentBlock / Claim / Decision，改为最小形态 `prose + rules[] + contracts[]`。
2. **删除全部跨层对齐校验**（如"ContentBlock 必须恰好引用每个 Claim/Decision 一次"）。
3. **Claim 并入 `rules[].evidence_ids + rationale`**；`Decision.statement` 删除，规则文本只在 prose 写一遍。
4. **`Decision.glossary/produces/required` → `contracts[] + contract_id + required_contracts`**，且 `rules[].rationale` 改为必填。
5. **一致性审查从"靠模型自觉"改为契约机制**（机器可校验：required_contracts 存在性、contract_id 合法性、消费章节 prose 术语漂移扫描）。
6. config：移除 `chapter_max_claims/decisions`，新增 `chapter_max_rules`。

#### 改动原因
针对上一批次暴露的三个问题：
- **① 重复表达**：正文本质是 Decision 的散文复述，Claim 层又独立写一遍事实句，形成三套文本。
- **② 脱链与凑数**：Claim 大量未被 Decision 引用（q6 26/70、q7 15/80、q8 22/80），模型在顶满字段上限。
- **③ 成本高**：37 次 submit_chapter 失败（14 缺 required decisions / 14 正文超预算 / 8 跨层对齐），每次失败带更长上下文重跑，是 supervisor 题 2000s+ 的重要来源。

| schema 校验/提交失败 | 37 次 | 6 次（58 校验中 52 通过） | ↓ 显著，跨层对齐类归零 | ①②③ |
| 工具成功率 | 95.5% | 98.7% | ↑ 3.2pp | |
| 交付 packet | 33 | 23 | ↓ 更少更密（去重） | ① |

> ⚠️ **成本下降需打折看待**：本批同时上线了 `ba70c78`（定价改人民币 + 缓存命中分档计费），¥11.57 中相当一部分来自计费口径变化，不能全部归因于重构。真实的 token 下降信号是"worker 阶段 prompt 6.25M + unknown 5.9M"（3 题 supervisor），但上批无同口径数据，无法直接对比。

**逐条对照**：
- ① 重复表达 → **消除**：packet 33→23，不再有 Claim 独立复述。
- ② 脱链与凑数 → **显著缓解**：schema 失败 37→6，跨层对齐失败归零。
- ③ 成本 → **名义大降**（扣除计费口径后仍应低于上批），但见"未达预期"。

#### 未达预期 / 出现的新问题

| 指标 | 上一批次 | 当前批次 | 目标 | 状态 |
|---|---|---|---|---|
| supervisor 模型调用/题 | ~103 | ~133 | 40~60 | ✗ **反升** |
| supervisor 耗时(s) | ~2032 | ~2119 | 600~900 | ✗ 持平 |

新问题：
1. **运行时失败反增**：上批 1 失败（q9），本批 2 失败（q6、q10，均 HTTP 400 tool_calls 配对断裂）；q6 上批曾 completed 本批失败。
2. **模型调用/题与耗时未降反升/持平**：重构去重的是"单次输出体积"，但调用次数与耗时仍是瓶颈，说明**优化方向 A（输入侧上下文压缩/检索预算）未同步落地**。
3. **一致性仍 C**：契约机制已实现但 judge 仍见真实跨章矛盾（q7 生存性权重、q8 事件-后果冲突、q9 拦截概率公式），且 terminology-drift 自动检查大量贪婪子串误报掩盖真实信号。
4. **遗留问题未动**：q3 再次 incomplete（预算耗尽）、q4 再次 routed_away（路由误判），与本轮改动无关。
5. **交付章节 38→23**：packet 更密但数量明显下降，需确认是否影响覆盖粒度（是否过少）。
6. **阶段归因大量 unknown**：本批 184 次调用、5.9M prompt tokens 落入 unknown，成本结构无法精确核对。

## 对比 #2：b_20260817_0028 vs b_20260816_0014

> 本轮改动：`65cb2fe`（per-chapter 检索预算 + 边际证据信号）· `85fc34b`（llm 评估第二版）
> 基准：0014 基于 `c7621ac`；0028 基于 `85fc34b`。两批同用一套题（question_set hash 相同），
> **均仍跑在旧一致性代码上**（术语机械扫描 + 整章重跑），尚未含 `c540066` 的评审就地修复。

### 一、改动内容与改动原因

#### 改动内容
1. **落地方向 A「每章检索预算」**：新增 `max_search_per_worker`（默认 5，env `RESEARCH_MAX_SEARCH_PER_WORKER`），对 chapter worker 的 `search_knowledge` 调用设硬上限；fast agent 保持 step-bound 不限。（对应 §7-8 中此前"规划未落地"的部分）
2. **边际证据信号**：`search_knowledge` 返回 `budget_reached`（镜像 `read_evidence` 的语义）与 `new_uncovered`（共享池之外的新证据数），worker 在边际收益归零时停止广搜。
3. **接线与测试**：worker prompt 写明预算与新证据停止条件；service 把 config 旋钮接进 `AgentRuntime`；+4 测试覆盖 budget 软信号与 new_uncovered 计数。

#### 改动原因
对比 #1 的遗留缺口：0014 中 supervisor q7/q8/q9 每题 184/162/210 次检索、模型调用 126→148，"模型调用/题与耗时未降"的主要来源是 worker 广搜无度、上下文被重复证据撑大。本改动正是对比 #1 标注为"未同步落地"的优化方向 A（输入侧上下文压缩/检索预算）。

### 二、改动结果

#### 改进效果

**同题可比（q7，两批均 completed）：**

| 指标 | 0014 | 0028 | 变化 |
|---|---|---|---|
| q7 耗时(s) | 1780 | 802 | ↓ ~2.2× |
| q7 模型调用 | 126 | 35 | ↓ ~3.6× |
| q7 工具次数 | 245 | 57 | ↓ ~4.3× |
| q7 检索次数 | 184 | 35 | ↓ ~5.3× |
| q7 去重引用 | 78 | 70 | ≈（产出粒度基本不变） |
| q7 成本(¥) | 3.11 | 1.03 | ↓ ~3× |

**批次级（含完成率干扰，见"需打折"）：** 检索 去重前 5378→1043、去重后 1758→609、实际引用 295→148；模型调用 426→104、成本 ¥11.57→¥2.65；阶段归因 unknown 184 次调用→**消失**；fast 段 q1/q2/q5 耗时约 45→33s（轻改善，fast 本已 step 受限）。

逐条对照：
- 每章检索预算 + 边际信号 → **显著收敛（q7 为据）**：检索 184→35、调用 126→35，而去重引用仅 78→70，说明"止于边际收益归零"确实压掉了无效广搜，未牺牲产出粒度。

#### 未达预期 / 新问题

| 指标 | 0014 | 0028 | 状态 |
|---|---|---|---|
| 失败数 | 2（q6/q10） | 3（q6/q8/q9） | ✗ 反增 |
| supervisor 完成题数 | 3（q7/q8/q9） | 2（q7/q10） | ✗ 减少 |
| 规划章节 / 已组装 | 23 / 7 | 15 / 6 | ✗ 下降 |
| q7 一致性 | C | C | ✗ 持平 |

新问题：
1. **q8/q9 由成转败，失败反增**：q8 `LengthFinishReasonError`（reasoning_tokens=62047 顶满 65534 完成 token）、q9 `BadRequestError`（tool_calls 配对断裂）、q6 `OutputParserException`——均为基建/模型侧，**与检索预算改动无因果**，是对比 #1 已出现的同源基建失败复现。
2. **批级"大降"需打折**：104 vs 426 调用、¥2.65 vs ¥11.57、去重后 1758→609，一部分源于 0028 完成 supervisor 题少（3→2）且失败题记 0 调用，**不能全归因于预算**；真实增益以同题 q7 为准。
3. **一致性仍 C**：q7「三级 vs 四级/Ⅰ–Ⅳ」跨章矛盾两批均存在；q10 另有 11 条术语/字段别名漂移。这两批都未含一致性修复，根源改动（`c540066` 评审就地修复）**尚未进任何一批**——需要改动后重跑才能验证，目前无对照。
4. **q3 两次均 incomplete**（预算耗尽）、**q4 两次均 routed_away**（路由误判），与本轮改动无关，持续未决。
5. **阶段归因 unknown 归零**（0014 的 184 次 / 5.9M prompt → 0028 无 unknown）：成本结构可精确核对（部分亦因完成题数少，仅作观测）。
