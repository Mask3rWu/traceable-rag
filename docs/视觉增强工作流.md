# LM Studio 视觉增强工作流

该工作流只处理解析结果中的 `figure` 和 `table`，向 LM Studio 的 OpenAI 兼容接口发送裁剪图，并要求模型输出最小结果：

```json
{
  "visual_type": "table|chart|flowchart|diagram|technical_drawing|photo|formula|other",
  "description": "图片中明确可见内容的简短描述"
}
```

原始 `doc.json` 不会被改写。每个文档旁边生成 `visual_enrichment.json`，其中每项都保留 `document_id`、`block_id`、页码和裁图路径，便于后续 chunk 与原图回链。模型结果是检索辅助信息，不是解析层事实。

## 1. 启动 LM Studio

在 LM Studio 中加载支持图片输入的 instruct 模型，启动 Local Server，默认地址为 `http://localhost:1234/v1`。记下 LM Studio 显示的模型标识。

## 2. 先处理单个文档

在项目根目录执行：

```powershell
python -m src.data_processing.visual_enrichment `
  processed/parsed/2-电子系统/doc.json `
  --model "<LM Studio 中的模型标识>"
```

输出文件：`processed/parsed/2-电子系统/visual_enrichment.json`。已有 `status=ok` 的块会跳过；使用 `--force` 重新生成。

## 3. 批量处理

先用少量文档观察效果：

```powershell
python -m src.data_processing.visual_enrichment `
  --all `
  --parsed-root processed/parsed `
  --limit 3 `
  --model "<LM Studio 中的模型标识>"
```

确认输出质量后再去掉 `--limit`。脚本按文档和图片逐项处理，单张图片失败只会在该项写入 `status=error`，不会中断其他图片。

## 4. 上下文策略

每次请求包含：所属 `section_path`、已配对的图注、引用该图表的正文、同章节邻近正文，以及块自身已有文本（表格 OCR/HTML）。上下文只用于帮助模型识别术语和用途；最终描述仍要求只写图片中明确可见的内容。

后续切 chunk 时，读取 `doc.json` 和 `visual_enrichment.json`，以 `block_id` 连接：图注/OCR/正文是主证据，`description` 作为低权重的视觉检索辅助文本，命中后返回原图、页码和 `block_id`。
